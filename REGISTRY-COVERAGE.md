# Registry coverage review

Reviewed 2026-10-11 against official docs and upstream source. The registry has 78 entries: 63 opt-outs, 3 opt-in checks, and 12 manual or unsupported controls. This review added 35 entries. Tests derive counts from registry data.

`init`, `doctor`, and `check` detect direct npm dependencies. Empty `packages` arrays mean no verified npm match. Other tools are available through `run`, `list`, and `why`. Versions, other manifests, and saved configuration are not inspected.

Recommended assignments and accepted values require evidence. Tool flags and SDK configuration may override environment values. Server controls apply to that server. `run` does not block networking or application telemetry.

Audit corrections:

- Removed unverified npm matches for Azure CLI, Google Cloud SDK, SAM, GitHub CLI, Stripe CLI, Meilisearch, and Flyway.
- Narrowed Prisma, CDKTF, CDK, Cube, Capacitor, Railway, Hookdeck, and AWS Blocks matches to the documented component.
- Prisma 7.8.0 accepts non-empty `CHECKPOINT_DISABLE`; 8.0.0-rc.1 introduced `PRISMA_DISABLE_TELEMETRY`. Both entries match `prisma` because versions are not parsed. The assignments are compatible.
- Yarn 2+ supports `YARN_ENABLE_TELEMETRY=0`; Classic does not. Package detection cannot distinguish them.
- Sentry CLI remains unsupported. Its [configuration source](https://github.com/getsentry/sentry-cli/blob/master/src/config.rs) did not verify `SENTRY_CLI_NO_TELEMETRY`. SDK reporting requires separate configuration.
- Angular source accepts `false` and `0`; Hookdeck/Stripe document `1` and `true`. CDKTF/Flyway/Claude use non-empty semantics. Recommended shared `CHECKPOINT_DISABLE=1` assignments agree across clients.
- Google Cloud is now `opt-in`, matching its [installation default](https://docs.cloud.google.com/sdk/docs/usage-statistics). [Property naming](https://docs.cloud.google.com/sdk/docs/properties) and the [core reference](https://docs.cloud.google.com/sdk/gcloud/reference/topic/configurations) verify the environment control. Saved preferences are not inspected.
- Firebase requires logout, then login and declining the usage prompt. Its login command has no `--no-enable-analytics` flag.
- Gemini's [parser](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/telemetry/config.ts) accepts `true` and `1` for OpenTelemetry export. Gemini settings and Better Auth configuration can also enable telemetry; neither is scanned.
- GitHub CLI telemetry begins in v2.91.0. Its control excludes extensions and Copilot.
